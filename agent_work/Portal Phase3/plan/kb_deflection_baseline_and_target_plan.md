# KB Deflection Baseline And Target Plan

## Slice

Portal Phase3 Iteration 14

Name: KB deflection baseline and target

## Why This Slice Exists

The 24 May portal gap analysis identified the KB deflection objective as only partially complete. Existing portal infrastructure already supports deflection tracking and helpfulness capture, but the programme still lacks:

- a visible baseline
- an explicit target threshold
- a small observable way to judge progress against the 20-30% objective

This slice should stay governance-sized rather than expanding into full reporting or dashboard redesign.

## Behavioural Goal

Portal operators should be able to see a concrete KB deflection baseline and whether current performance is above or below the configured target band.

## Scope

In scope:

- establish a configurable KB deflection target range
- surface a current baseline / current-rate view through the running software
- preserve existing deflection tracking and helpfulness behaviour

Out of scope:

- broad analytics dashboarding
- knowledge-base content quality tooling
- recommendation/routing redesign
- unrelated portal reporting cleanup

## Expected Outcome

The running portal exposes a small, coherent, management-usable deflection status outcome instead of leaving the 20-30% target implicit.
