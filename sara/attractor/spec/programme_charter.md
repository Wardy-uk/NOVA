# SARA Programme Charter

## Purpose

Create SARA as a persistent, context-aware personal operating layer with one shared understanding of Nick's world across embodiments.

## Protected Architectural Decisions

1. There is one SARA brain and one shared state model.
2. Context precedes conversation.
3. The State Engine is the architectural centre.
4. The long-term model is single brain, multiple embodiments.
5. Home Assistant is the telemetry bus, not the decision engine.
6. Nodes are interfaces, not brains.

## Governance Rules

- Work only through bounded workstreams and phase-sized build briefs.
- Keep implementation and evaluation context separated.
- Require behavioural evaluation for convergence.
- Prevent WS0 from drifting into WS3-WS6 concerns.
- Preserve shared-state assumptions even when using stubs or hardcoded runtime values.

## Current Scope Boundary

Only WS0, WS1, and WS2 are in programme scope.

- WS0 is the active delivery slice.
- WS1 and WS2 may be planned but not implemented unless explicitly activated.
- WS3 through WS6 remain not started.
