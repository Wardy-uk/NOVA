## 1. What was delivered

All work is **new, additive, and parallel**. It builds directly on the converged
Phase 1 foundation (`KpiEngine`, business-hours engine, pluggable computers,
`kpi_*` tables) and the Regression-Protected Phase 2 slice (`KpiEodService`,
`kpi_daily` / `kpi_agent_daily` / `kpi_eod_snapshot`). The legacy KPI system —
n8n workflow, `techservicesjsm` tables, `kpi-pipeline.ts`, `/api/kpi-data/*`,
`/api/trends/*`, the legacy KPI React views, and the legacy `/wallboard/*`
routes — was **not touched** and keeps running in parallel.

### New read-model service — `src/server/services/kpi-engine/kpi-views.ts` (`KpiViewsService`)

Composes the Phase 3 view payloads entirely from the clean-sheet `kpi_*` tables
(NOVA main pool) via the Phase 1 engine and the Phase 2 EOD service. No legacy
pool, no `techservicesjsm`, no forbidden table.

- `getSltSummary()` — one card per space; SLT-flagged metrics resolved to their
  current value (latest live snapshot, falling back to the most recent frozen
  daily value) + RAG.
- `getTeamDashboard(spaceKey)` — full enabled-metric grid with current
  value/target/RAG + 7-day daily history, per-tier breakdown (NT), and the most
  recent frozen EOD ticket-state snapshot.
- `getLeaderboard(spaceKey, date?)` — agent scorecard for the most recent
  captured agent date (≤ requested date), with a composite attainment score.
- `getSpaceMetricBindings(spaceKey)` — enabled bindings incl. the `show_on_slt_view`
  / `show_on_wallboard` flags (used by SLT, team, and the wallboards).

RAG on "current" values reuses the Phase 2 `computeRag()` (configurable
target + amber-band %, direction-aware) — no hardcoded SLA targets.

### New API endpoints — `src/server/routes/kpi-engine.ts` (existing `/api/kpi/*` family, no namespace change)

| Endpoint | Required outcome | Notes |
|---|---|---|
| `GET /api/kpi/slt` | **(1)** SLT cross-space data source | Latest cross-space summary |
| `GET /api/kpi/team/:spaceKey` | **(2)** team dashboard data source | 404 on unknown space |
| `GET /api/kpi/leaderboard/:spaceKey` | **(3)** agent scorecard data source | optional `?date=YYYY-MM-DD` |

All follow the repo `{ ok, data }` / `{ ok, error }` convention. `views` is wired
through `KpiFoundation` and the route factory from `index.ts`. No collision with
the legacy inline `POST /api/kpi/derived/run` (different paths). Design §9 names
`/api/kpi/slt` and `/api/kpi/leaderboard/:spaceKey`; the supporting reads
(`/snapshot/:spaceKey`, `/daily/:spaceKey/:date`, `/agent/:spaceKey/:date`,
`/eod/:date`) already existed from Phases 1–2 and are reused.

### New React views — clean-sheet KPI platform (parallel to legacy KPI views)

Three lazy-loaded components, wired into a **new, additive** App area
**"KPI Platform"** (`kpi-platform`) so they sit clearly alongside — never on top
of — the legacy "KPIs" area:

- `KpiCleanSltView.tsx` — **(1)** SLT cross-space dashboard (card per space).
- `KpiCleanTeamView.tsx` — **(2)** team dashboard with space selector, metric
  grid (value/target/RAG/7-day sparkline), tier breakdown (NT), and EOD snapshot.
- `KpiCleanAgentView.tsx` — **(3)** agent scorecard/leaderboard with composite
  ranking and a click-through per-agent breakdown.

App wiring is fully additive: new `Area`/`View` union members, a new `AREAS`
entry + tab set, `AREA_ORDER`, `FULL_WIDTH_VIEWS`, default+admin area-access
entries, and a `canSeeArea` clause making the area visible to all authenticated
users (design §13.8). No legacy view, route, or area definition was modified.

### Wallboards rewired to the clean-sheet data source — **(4)**

## 2. What remains incomplete or bounded

- **Computed-data depth is inherited from Phases 1–2.** Views render whatever the
  engine/EOD has captured. Where a Jira space has sparse or no snapshot/daily data
  (notably **STBY**, whose sync coverage may be absent), the views show an honest
  empty state ("No clean-sheet data captured yet…") and `—` for missing values —
  **no fabricated zeros**.
- **Manual / non-Jira spaces (CS, KAM, ONBOARD, COMMS)** are listed and labelled
  honestly ("Manual / non-Jira team — captured via manual entry (not in computed
  scope yet)") with `—` values. Their actual capture is Phase 4 (manual
  entry/import), which is deliberately **out of scope** here.
- **Agent scorecard columns are bounded to the agent metrics that have a Phase 2
  computer** (`frt_compliance`, `resolution_compliance`, `frt_avg_minutes`,
  `resolution_avg_minutes`, `resolved_today`, `csat_score`). Other `is_agent_level`
  metrics without a computer simply show `—` — unchanged Phase 1/2 boundary.
- **Wallboard headline-metric selection uses a documented fallback.** No seed row
  currently sets `show_on_wallboard = 1`, so the clean-sheet wallboards fall back
  to `show_on_slt_view` metrics, then to the first enabled metrics by display
  order. This is explicit in code and honest in behaviour; flipping `show_on_wallboard`
  later (admin UI is Phase 5) will take effect with no code change.
- **Trend depth = available `kpi_daily` history.** The team-dashboard sparkline is
  a 7-day window over frozen daily rows; with few captured days it renders the
  points it has (or nothing) rather than padding.
- **No Phase 4/5 scope was added:** no manual-entry UI, no spreadsheet import, no
  AI digest, no config/admin UI. View delivery + wallboard rewiring only.

## 3. Assumptions required

1. **`/api/kpi/*` is reachable without auth** (as mounted in Phase 1 and used by
   the prior evaluations), so the new React views and the public TV-display
   wallboards read it directly — consistent with design §13.8 ("all views visible
   to all authenticated users for now").
2. **"Current" value = latest live snapshot, else most recent frozen daily.** This
   keeps the SLT/team views live during the day yet still meaningful out-of-hours
   (when no fresh snapshot exists) without inventing data. The provenance
   (`valueSource`: `snapshot`/`daily`) and `asOf` timestamp are returned so
   staleness is visible rather than hidden.
3. **Composite agent score = mean attainment vs target** across the agent's
   target-bearing metrics: direction-aware (higher-is-better `value/target`;
   lower-is-better `target/value`), clamped to 0–150%, expressed as a percentage.
   Agents with no target-bearing metric get a null composite and rank last. This
   is a transparent, defensible ranking; it is surfaced in the UI footnote.
4. **A new App area is the right home** for the three new views (rather than extra
   tabs inside the legacy "KPIs" area), to keep the parallel system visibly
   separate per the "everything new, nothing modified" principle. The area is
   visible to all authenticated users; no role/permission seeding was required.
5. **New wallboard routes rather than edits to legacy ones** satisfy "rewire
   wallboards to the clean-sheet data source" while honouring "keep the legacy KPI
   system untouched and running in parallel." Both data sources coexist; cut-over
   is an operational decision (display URL swap), not a code change here.
