# Phase 1 Iteration 3 Behavioural Routing

## Routing Decision
Another iteration is required. The main portal journey is now functioning well, but convergence is still blocked by one remaining customer-visible inconsistency: status wording is not yet fully aligned across all visible support surfaces.

## Remaining Behavioural Gap
The conversation sidebar still shows internal-style status wording after a request is submitted. This creates a mismatch with the customer-facing language now used elsewhere in the portal experience.

## Customer-Visible Problem
Customers can move through a clear request flow, receive confirmation, and reach a created ticket, but then still encounter wording in the sidebar that does not feel customer-facing or self-explanatory. That inconsistency weakens the sense that the portal is a curated, coherent support journey.

## Operational Impact
Even when the underlying support flow is working, inconsistent visible language can reduce trust in the portal and make customers less certain about what stage their request is in. A polished journey is undermined if one common surface appears to expose internal phrasing instead of clear customer-safe progress language.

## Scope Reminders
- Preserve the working intake flow.
- Preserve the working ticket creation experience.
- Preserve the working conversational progression from first message through submission.
- Avoid broad redesign or unrelated portal changes.
- Keep this iteration tightly scoped to the remaining wording inconsistency.

## Behavioural Priorities
- Ensure customer-facing status wording remains consistent across all visible support surfaces.
- Remove the remaining customer-visible use of internal-style status language.
- Keep the portal journey understandable and curated from conversation through ticket confirmation.
- Protect the already-converged behaviours in ticket list, ticket detail, timeline, and fresh request progression.

## Convergence Guidance
This slice likely converges when the customer can complete the same successful portal journey already observed, and every visible status or progress label in that journey reads as consistent, customer-facing language. Convergence should preserve the working flow while eliminating the remaining wording mismatch in the sidebar experience.
