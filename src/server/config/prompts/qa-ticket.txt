## Your Task

Score this ticket across multiple quality dimensions:

1. **overallScore**: 1-10 overall quality score (computed as: accuracy×0.35 + clarity×0.25 + tone×0.20 + closure×0.20)
2. **accuracyScore**: 1-10 — was the diagnosis correct? Was the fix appropriate?
3. **clarityScore**: 1-10 — were responses clear and understandable?
4. **toneScore**: 1-10 — was the tone professional, empathetic, appropriate?
5. **closureScore**: 1-10 — did the agent properly resolve or advance the ticket? Was the resolution communicated clearly?
6. **grade**: "Green" (8-10), "Amber" (5-7), or "Red" (1-4) based on overallScore
7. **isConcerning**: true if there's a specific quality issue that needs attention
8. **severity**: "low", "medium", or "high" — only meaningful if isConcerning is true
9. **category**: The primary quality dimension that drives the overall score
10. **summary**: 1-2 sentence summary of the QA assessment
11. **issues**: Key issues identified in this ticket (1-2 sentences, or empty string if none)
12. **customerSentiment**: "positive", "neutral", or "negative" — the customer's apparent sentiment
13. **firstReplyAssessment**: Score the first agent reply specifically — was it timely, relevant, helpful?
14. **closureAssessment**: Score the closure — was the resolution communicated clearly? Was the customer informed?
15. **issuesFound**: Array of specific quality issues found (empty if none)

## Resolution Quality Checks

In addition to the QA scores above, assess the resolution against four pass/fail checks:

16. **resolutionChecks.clarity** — Is the resolution clearly documented? Can someone understand what was done?
    - passed: true/false
    - detail: one sentence explaining why it passed or failed
    - A one-word close ("sorted", "fixed", "done") with no explanation FAILS this check
    - A clear description of what was done and why PASSES

17. **resolutionChecks.customerCommunication** — Was the customer informed of the resolution?
    - passed: true/false
    - detail: one sentence
    - If the ticket was closed with only internal comments (no public reply explaining the resolution), this FAILS
    - If the last public comment explains what was resolved and what to expect, this PASSES

18. **resolutionChecks.completeness** — Were all reported issues addressed?
    - passed: true/false
    - detail: one sentence
    - If the customer mentioned multiple issues and only some were addressed, this FAILS
    - If all issues were addressed (or unaddressed ones were explicitly noted as separate tickets), this PASSES

19. **resolutionChecks.resolutionTypeMatch** — Does the Jira resolution type match what actually happened?
    - passed: true/false
    - detail: one sentence
    - If the resolution type is vague or wrong ("No Fault Found" on a ticket with a clear fault, or "Done" with no context), this FAILS
    - suggestedType: what the resolution type should be, or null if it's correct

## Scoring Guide
- 9-10: Exemplary — could be used as training material
- 7-8: Good — meets standards with minor room for improvement
- 5-6: Acceptable — gets the job done but notable gaps
- 3-4: Below standard — significant issues that need coaching
- 1-2: Poor — fundamental problems with the interaction

## Rules
- Score based on what actually happened, not what you'd have done differently
- If the ticket was resolved quickly and correctly, that matters more than perfect prose
- A simple fix done well deserves a good score — don't penalise simplicity
- Flag concerning behaviour only for genuine issues (rude tone, wrong fix, security risk)
- If the ticket was resolved by an automated process, score the process appropriately
- For resolution checks: be fair but firm. Don't fail for minor style issues — focus on whether the customer would understand what happened
- If the ticket was auto-closed (e.g. no reply from customer), the resolution may legitimately be brief — judge accordingly
- Consider the ticket type: a simple how-to may not need a detailed resolution, but an incident or bug should document root cause
